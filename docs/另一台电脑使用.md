# 在另一台电脑使用

GitHub 保存本工作台源码。下载后可以继续开发；作品文件、模型密钥和本机 Codex 登录不会跟着源码自动同步。

## 下载源码

使用同一个 GitHub 账号登录你的仓库，点击绿色 **Code → Download ZIP**，解压即可。准备长期在两台电脑间继续开发时，安装 Git，使用 **Code** 菜单里的仓库地址克隆；改动要提交并推送后，另一台电脑才能拉取。

## 从源码运行

安装 Node.js 24、pnpm 11.7.0。在解压或克隆的仓库根目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

第一次安装会下载 Electron。构建使用 `pnpm build`。Windows 安装包沿用现有入口：

```powershell
pnpm --dir apps/desktop exec electron-builder --config electron-builder.yml --win nsis --x64 --publish never
```

当前 GitHub 源码版去掉了作者的私有文风包；不会在启动时把作品样本导入新电脑。需要自己的参考资料时，在工作台中明确选择和导入。源代码中的工程测试样例不能作为创作资料。

## 作品与模型

在原电脑通过工作台“同步与备份”保存作品备份，或复制明确的作品文件夹；在新电脑工作台中打开或导入。不要把整个 AppData、聊天目录或包含密钥的配置上传到源码仓库。软件源码更新也不会自动合并两台电脑对同一篇正文的修改。

当前聊天菜单支持导出当前对话，但导出文件是阅读副本，不能承诺导入后恢复原会话及模型上下文。当前模型配置也没有统一的导入导出按钮；在新电脑设置中重新配置。统一的作品、聊天、模型配置迁移包尚未实现，不能把下载 GitHub 源码当作个人数据恢复。

模型服务在新电脑的设置里重新配置。要让工作台调用 Codex，还需在新电脑安装官方 Codex 并登录；后台接入使用该电脑实际返回的模型目录和额度。这里的助手调用工作台时，工作台必须正在运行；连接文件由新电脑生成，不复制旧电脑的连接凭据。

## 双向协作

进入长篇后点击上方“创作协作”，可核对要求、检索前文、比较多个模型候选或请 Codex 独立讨论。保存仍是候选，不自动覆盖正文或登记正典。

本仓库 `tools/novel-workbench-client.mjs` 提供本机后台入口。启动工作台后，助手可运行 `node tools/novel-workbench-client.mjs` 查看作品及模型配置；后续使用 `--request-file` 请求准备、生成、取回或保存。需要 MCP 时使用 `--mcp`，由聊天客户端配置加载。连接文件包含本机凭据，不要粘贴或分享。
